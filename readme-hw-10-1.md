# Домашнє завдання 10-1

Реалізувати дві функції видачі решти і порівняти їх ефективність:
- `find_coins_greedy(amount)` — жадібний алгоритм
- `find_min_coins(amount)` — динамічне програмування

Набір номіналів: `[50, 25, 10, 5, 2, 1]`.

## Складність алгоритмів

**Жадібний** — O(n), де n — кількість номіналів. У нашому випадку номіналів
лише 6, тому фактично алгоритм працює за константний час O(1) незалежно
від суми.

**Динамічне програмування** — O(amount × n), де amount — сума, а n —
кількість номіналів. Час лінійно росте зі збільшенням суми.

## Результати вимірювань

| Сума | Жадібний | DP |
|---:|---:|---:|
| 113     | 0.000033 с | 0.002685 с |
| 1 000   | 0.000019 с | 0.028250 с |
| 10 000  | 0.000020 с | 0.298610 с |
| 100 000 | 0.000032 с | 3.848764 с |

## Висновки

- На малих сумах різниця ще не дуже велика, але вже помітна — DP у 80 разів
  повільніший за жадібний для суми 113.

- Зі збільшенням суми DP стає все повільнішим: для 100 000 він працює
  майже 4 секунди, тоді як жадібний усе так само завершує за мікросекунди.

- Для нашого набору монет `[50, 25, 10, 5, 2, 1]` обидва алгоритми
  повертають однакову відповідь, бо цей набір зручний для жадібного —
  він тут дає правильну відповідь.

- Важлива примітка: жадібний підходить тільки для канонічних наборів.
  Наприклад, для набору `[1, 3, 4]` і суми 6 жадібний дав би 4+1+1
  (3 монети), хоча оптимально 3+3 (2 монети).
